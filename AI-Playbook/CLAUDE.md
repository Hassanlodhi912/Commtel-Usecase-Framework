## 2. Register conventions

- L1 = Cyber Kill Chain stage code: RE, WE, DE, EX, IN, CC, AO (plus TG, MW, CM for other threats).
- L2 = MITRE tactic code, for example WE-002 Execution, DE-005 Stealth (was Defense Evasion), DE-041 Defense Impairment (new in ATT&CK v20), EX-006 Credential Access, AO-040 Impact.
- L3 rule identifier = `<L2>-<Technique>`, for example `WE-002-T1053.005`.
- CUC numbers are permanent. Never reuse a retired number. New techniques get the next free number.
- Effectiveness, implementation and coverage columns stay **0** until use cases are implemented at clients (future phase).
- When a use case is documented: add its folder, add a row to the README use case table, update the README progress table, add the GitHub link in the register (L3 sheet, Document column).

## 3. Writing rules

- Use the wording "Commtel Usecase Framework". Never write the word "MaGMa" anywhere.
- No AI attribution anywhere: no "Co-Authored-By: Claude", no "generated by AI" lines in commits, documents or code. Commit as `Hassanlodhi912 <Hassanlodhi912@users.noreply.github.com>`.
- Do not state in client documents that a client lacks a log source (for example PowerShell logging).
- Use only facts from the documents, lab results or official sources (MITRE, vendor docs). Never invent test results.
- Never upload confidential material to this public repository (for example SBP-IR advisories, client names, client IPs).

## 4. Use case document structure

Every CUC document uses the branded Commtel template (`AI-Playbook/Templates/Commtel_CUC_Base_Template.docx`: cover page, logo, red E32229 tables, footer). Reference example: `Use-Cases/Weaponization/CUC-037_.../CUC-037_...docx`.

Sections, in order:

1. Scope (tactic, technique, kill chain phase, SIEMs covered, rule ID range)
2. Context (how attackers use the technique, real threat actor examples)
3. Detection Scope: Detection Technologies, Log Source Type, Scope, Prerequisites
4. Rule Logic: Sigma rule, Wazuh rules, QRadar reference (test conditions + AQL)
5. Payload Details (example log lines with the fields that matter)
6. SOPs to Tune, Expected Blindspot
7. Validation: Lab Environment, Validation Procedure, Detection Results, Key Observations, SIEM Alert Evidence (screenshots with yellow highlights)
8. False Positive scenarios
9. Response: Investigation (L1 then L2 steps), Remediation
10. Appendix

Document names: `CUC-NNN_<L2>-<Technique>_<Name>.docx` and `.pdf`. Prepared By, Supervised By and Approved By names are given by the user for each document.

## 5. Wazuh lab conventions

- Lab: Wazuh all-in-one VM (manager, indexer, dashboard) and a Windows 11 victim VM, on a private VMware network. Ask the user for current IPs and SSH access.
- One rule file per use case: `/var/ossec/etc/rules/cuc_NNN.xml`, not `local_rules.xml`.
- Rule IDs: CUC-NNN uses 10NNN0 to 10NNN9 (CUC-037 -> 100370-100379, CUC-276 -> 102760-102769).
- Never use `<if_group>windows</if_group>`; chain with `<if_sid>` to the stock parent rules (4688 -> 67027, 4698 -> 60228, 4104 -> 91802, 1102 -> 63103, 104 -> 63104). Keep `windows` out of the group header.
- Before restarting the manager: stop wazuh-indexer and filebeat, run `wazuh-analysisd -t` under `systemd-run --scope -p MemoryMax=5G`, then restart and start indexer and filebeat again. The VM has limited RAM.
- Take a VM snapshot before big lab changes. Run Atomic Red Team tests only on the Windows victim VM.
- Validate that a rule fires on the true positive and does not fire on normal activity (false positive check) before writing results.

## 6. Firewall use cases

- Generate test logs with the Commtel Firewall Log Simulator, for example:
  `python commtel_log_simulator.py --vendor fortigate --scenario vpn_bruteforce --success --target <wazuh-ip>`
- Wazuh needs a syslog listener (`<remote><connection>syslog</connection>...`) for the lab subnet.
- Log formats from the simulator follow vendor documentation; map field names against one real client log before deploying a rule to production.

## 7. How to ask a new chat

1. Share this file (or the repository link) at the start of the chat.
2. Give the register row, for example `EX-006-T1110.001 | Password Guessing | CUC-380`.
3. Give the document names: Prepared By, Supervised By, Approved By.
